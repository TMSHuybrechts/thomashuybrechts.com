Repo Notebook

01 O PROBLEMA

Quem trabalha muito com open source junta centenas de repositórios: em separadores do browser, estrelas, notas e pastinhas soltas. Aí perde-se conhecimento. Porque guardou aquilo? Ainda funciona? Com o que se relaciona?

02 O QUE FAZ
Recolher sem atrito
Cole um URL de repo e ele fica guardado com README, estrelas, forks, linguagem e licença. Pesquisar, filtrar por categoria e estado, e um índice A–Z para coleções grandes.
Colheita
Cole uma conta GitHub, uma lista de nomes de ferramentas ou um URL de página (blog, Medium, linktree). A Colheita vai buscar a página, extrai todos os links GitHub e deixa-o escolher o que vai para o notebook. Nada é guardado até o marcar.
IA local
Categorias, resumos e sugestões vêm de um modelo de linguagem a correr localmente. Sem dados para a cloud, sem custos de API, funciona também offline.
Notas & estado
Por repo, uma nota própria (‘porque guardei isto?’) e um estado: a experimentar, instalado, agrada, arquivo. Assim a coleção continua viva em vez de virar um cemitério.
Mapa & Início rápido
Ver os repositórios como um mapa ligado e, com um clique, clonar ou abrir no GitHub.
Integração MCP
Através do Model Context Protocol, assistentes de IA podem pesquisar e ler diretamente no notebook — a base do plugin do Obsidian.
03 O QUE APRENDI
A IA local é rápida o suficiente para este tipo de trabalho se mantiver as tarefas pequenas: categorizar, resumir, sugerir. O maior ganho não estava no modelo, mas no workflow à volta — a Colheita e os botões de estado fizeram a diferença entre ‘útil’ e ‘usar todos os dias’.
