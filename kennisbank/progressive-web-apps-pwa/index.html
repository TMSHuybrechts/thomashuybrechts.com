Progressive Web Apps (PWA)

Een website die werkt als app

een PWA is een website die zich gedraagt als een app — installeerbaar, offline bruikbaar en bereikbaar zonder app store.

Wat is het?

Een Progressive Web App is een gewone webapplicatie, uitgebreid met app-achtige eigenschappen. De gebruiker kan hem op het beginscherm installeren, hij werkt (deels) offline en hij laadt razendsnel. Alles draait via de browser, zonder aparte app voor iOS of Android.

Hoe werkt het technisch?

  • De service worker is de kern: een script dat op de achtergrond draait en netwerkverkeer onderschept.
  • De service worker gebruikt de Cache API om pagina’s, data en assets lokaal op te slaan. Zo werkt de app zonder verbinding.
  • Het web app manifest (een JSON-bestand) beschrijft naam, iconen en weergavemodus. Dit maakt installatie op het beginscherm mogelijk.
  • Push API en Notifications API maken pushmeldingen mogelijk, ook als de app niet open staat.
  • HTTPS is verplicht: service workers werken alleen over een beveiligde verbinding.

Wat kun je ermee bouwen?

Een installeerbare webshop die offline de catalogus toont. Een orderapp voor vertegenwoordigers op locatie zonder bereik. Een nieuws- of intranetapp met pushmeldingen. Een boekingssysteem dat reserveringen lokaal opslaat en later synchroniseert.

Commercieel gebruik

je bespaart de kosten van twee native apps (iOS én Android) en onderhoudt één codebase. Geen app store-tarieven en geen review-procedures bij updates: elke deploy is direct live. Ideaal voor kmo’s die app-functionaliteit willen zonder app-budget. Ook aantrekkelijk als dienst: “uw bestaande webshop als installeerbare app”.

Sterke combinaties

Next.js of een ander modern framework voor de basisapp. IndexedDB voor gestructureerde offline data. Synchronisatie bij heropenen van de app of via WebSockets zodra er weer verbinding is; Background Sync werkt enkel in Chromium-browsers (niet op iOS). Een design system zorgt dat de app er op elk apparaat strak uitziet.

Belangrijkste 20%

  • De service worker bepaalt alles: cachingstrategie (cache-first voor assets, network-first voor verse data) is dé kernkeuze.
  • Offline is een glijdende schaal, geen aan/uit-schakelaar: bepaal bewust wélke delen offline moeten werken.
  • Ondersteuning verschilt per platform; behandel installatie en push als progressive enhancement, niet als vereiste.

Praktijkvoorbeeld (fictief)

een fietsenmaker met werkplaats- en verhuurafdeling. Monteurs openen de PWA op hun telefoon, zien de dagplanning en registreren reparaties — ook in de kelder zonder bereik. Zodra ze de app met bereik openen, synchroniseert alles automatisch. De klant krijgt een pushmelding als de fiets klaarstaat. Kosten: één webproject, geen app stores.
