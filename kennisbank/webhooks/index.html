Webhooks

Systemen die elkaar automatisch verwittigen

een webhook is een HTTP-callback waarmee een systeem een ander systeem direct en automatisch informeert dat er iets is gebeurd.

Wat is het?

In plaats van dat jij elke minuut vraagt “is er iets nieuws?” (polling), stuurt het bronsysteem zelf een bericht zodra er een event plaatsvindt. Een betaling gelukt, een formulier ingevuld: de data arriveert meteen bij jouw endpoint.

Hoe werkt het technisch?

  • Je registreert een endpoint-URL bij het bronsysteem, plus de gewenste eventtypes.
  • Bij een event stuurt de bron een HTTP POST met een JSON-payload naar die URL.
  • Jouw server antwoordt snel met een 2xx-statuscode als ontvangstbevestiging.
  • Verificatie: een shared secret of HMAC-handtekening bewijst dat de call echt van de bron komt.
  • Mislukt de levering, dan volgen doorgaans retries met toenemende intervallen.
  • Best practice: bevestig direct, verwerk daarna asynchroon via een queue.

Wat kun je ermee bouwen?

  • Realtime lead-notificaties vanuit websiteformulieren.
  • Betalingsbevestigingen die direct orders activeren.
  • CI/CD-triggers: een push naar de repository start automatisch een build.
  • Tweerichtingssynchronisatie tussen systemen zonder polling.

Commercieel gebruik

webhooks maken integraties realtime en goedkoop — geen continu pollen, dus minder serverbelasting en snellere processen. Ze zijn de lijm van vrijwel elke betaalde integratie tussen SaaS-producten. Voor je klanten: snellere reactie op leads en betalingen betekent direct hogere conversie.

Sterke combinaties

  • n8n en workflow-tools: webhook als trigger van complete automatiseringen.
  • Task queues: ontvangen events betrouwbaar asynchroon verwerken.
  • Event-driven architecture: webhooks als de externe poort van je eventstroom.
  • API-orkestratie: het webhook-event start de georkestreerde keten.

Belangrijkste 20%

  • Een webhook komt één keer binnen (hooguit met enkele retries): jij moet ontvangst snel bevestigen, verifiëren en robuust verwerken.
  • Maak je handler idempotent; dezelfde webhook kan door retries dubbel aankomen.
  • Antwoord snel (binnen enkele seconden) en schuif zwaar werk door naar de achtergrond.

Praktijkvoorbeeld (fictief)

een webshop koppelde zijn betaalprovider via een webhook aan n8n. Zodra een betaling binnen is, wordt automatisch een factuur aangemaakt, de voorraad bijgewerkt en de verzending aangemeld. Voorheen gebeurde dat handmatig, soms pas de volgende ochtend.
